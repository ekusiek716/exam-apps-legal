# お問い合わせフォームの設定手順（本人作業）

サポートサイトのお問い合わせフォームは、Google スプレッドシートに送信内容を1行ずつ書き込みます。
この手順は **Google アカウントの操作を伴うため、オーナー本人が行う必要があります**（AI エージェント・第三者は代行しません）。
費用はかかりません。

設定が終わるまでは、`_config.yml` の `contact_form_endpoint` が空のため、
お問い合わせページにはフォームが表示されず、メールアドレスだけが掲載されます。この状態でも公開して問題ありません。

## 1. スプレッドシートを作る

1. <https://sheets.google.com/> を開き、空白のスプレッドシートを新規作成する。
2. ファイル名は分かりやすいもの（例: `お問い合わせ受信箱`）にする。
3. シート名は変更しなくてよい。スクリプトが `contact` シートと見出し行を自動で作る。

## 2. Apps Script にコードを貼る

1. そのスプレッドシートのメニューから **拡張機能 → Apps Script** を開く。
2. 最初から入っている `function myFunction() {}` を全部消す。
3. このリポジトリの `tools/contact-form.gs` の中身を全部コピーして貼り付ける。
4. 保存する（フロッピーディスクのアイコン、または Ctrl/Cmd + S）。

## 3. ウェブアプリとしてデプロイする

1. 画面右上の **デプロイ → 新しいデプロイ** を選ぶ。
2. 歯車アイコン（種類の選択）から **ウェブアプリ** を選ぶ。
3. 設定を次のようにする。
   - 説明: 任意（例: `お問い合わせフォーム v1`）
   - 次のユーザーとして実行: **自分**
   - アクセスできるユーザー: **全員**
     - ここを「全員」にしないと、サイトの訪問者からの送信が届きません。**必須です。**
     - 「全員」でも、スプレッドシートの中身が公開されるわけではありません。公開されるのは「書き込みを受け付ける窓口」だけです。
4. **デプロイ** を押す。初回はアクセス権限の承認を求められるので、自分の Google アカウントで承認する。
   途中で「このアプリは確認されていません」と警告が出た場合は、詳細を開いて自分のスクリプトとして続行する。
5. 表示される **ウェブアプリの URL**（`https://script.google.com/macros/s/.../exec` で終わるもの）をコピーする。

## 4. サイト側に URL を設定する

1. このリポジトリの `_config.yml` を開く。
2. `contact_form_endpoint: ""` の `""` の中に、コピーした URL を貼る。

   ```yaml
   contact_form_endpoint: "https://script.google.com/macros/s/xxxxxxxx/exec"
   ```

3. 変更をコミットして `main` に反映する。GitHub Pages のビルドが終わると、お問い合わせページにフォームが表示される。

## 5. 動作確認

1. <https://ekusiek716.github.io/exam-apps-legal/support> を開く。
2. フォームが表示されていることを確認する（表示されない場合は URL の貼り間違い、または YAML の引用符の閉じ忘れを疑う）。
3. テスト用の内容（本文に「テスト」など）を入れて送信する。ページが切り替わらず、その場に「送信しました」と出れば成功。
4. スプレッドシートの `contact` シートに、受信日時・種別・対象アプリ・本文・返信先メールの1行が増えていることを確認する。
5. 本文の先頭に `=` を入れたもの（例: `=1+1`）でもう一度送り、スプレッドシートのセルに
   `=1+1` と**文字のまま**表示されることを確認する（`2` と計算されて表示されたら、
   数式として実行されている。`tools/contact-form.gs` を貼り直して再デプロイする）。
6. 「アクセスできるユーザー」を**全員**にし忘れていると送信は失敗する。その場合に
   フォームへ「送信できませんでした」と表示され、メールでの問い合わせへ案内されることも
   一度確認しておくと安心（設定を一時的に戻して試す）。
7. うまくいかないときは、コードを直した後に必ず **デプロイ → デプロイを管理 → 編集（鉛筆）→ バージョン: 新バージョン → デプロイ** を行う。
   保存しただけでは公開中のウェブアプリには反映されない。

## 6. 迷惑メール（スパム）が増えた場合

フォームには無料でできる範囲の対策をあらかじめ入れてあります。

- 人間には見えない入力欄（ハニーポット）に入力があった送信は保存しない
- 本文は2000文字までに制限し、超過分は切り詰める
- ページを開いてから3秒未満で送信されたものは保存しない

それでも自動送信が続く場合は、次の順で検討します。

1. スプレッドシートを見て、どんな内容が届いているかを確認する（多くは英文リンクの宣伝）。
2. Apps Script の `MIN_ELAPSED_SECONDS` を大きくする（例: 5）。
3. 止まらなければ、Cloudflare Turnstile（無料の CAPTCHA 代替）の導入を検討する。導入にはフォーム側と Apps Script 側の両方の改修が必要。
4. 緊急時は `_config.yml` の `contact_form_endpoint` を `""` に戻せば、フォームは非表示になり、メール窓口だけになる。

## 補足

- 受信内容の取り扱いは、プライバシーポリシーの「1.8 サポートページのお問い合わせフォーム」に記載済み。**法務文書の変更にあたるため、公開前に本人の確認が必要。**
- スプレッドシートは自分の Google ドライブ内に残るため、第三者サービスへの課金・データ預け入れは発生しない。
- 返信は、スプレッドシートの「返信先メール」列のアドレスへ、通常のメールで行う。
